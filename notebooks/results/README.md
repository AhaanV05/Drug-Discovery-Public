# Results

**The study:** which strategy best controls the properties of generated molecules?
Four arms, same 200k ChEMBL dataset, same evaluation harness, same operating point.

| Stage | Arm | Strategy | Status |
|---|---|---|---|
| **1** | conditional diffusion, **1 property** (QED) | conditioning | ✅ trained (ep46) |
| **2** | conditional diffusion, **9 properties** + per-property dropout | conditioning | ✅ trained (ep47) |
| **3** | RL fine-tune of the Stage-2 policy | weight optimisation | ✅ trained (1000 steps, β=0.05) |
| **4** | filtered-unconditional baseline (QED > 0.5 subset) | none — train on good data | ✅ trained (ep55) |

---

## The headline

| | steering range | joint target, top-50 (lower better) | uncond. meanQED |
|---|---:|---:|---:|
| **Stage 1** (1 prop) | **0.682 ± 0.011** | 0.247 ± 0.012 | 0.692 |
| **Stage 2** (9 prop) | 0.555 ± 0.004 | **0.134 ± 0.009** | 0.712 |
| **Stage 3** (RL) | 0.546 ± 0.005 | 0.140 ± 0.005 | 0.687 |
| **Stage 4** (filtered) | 0.577 ± 0.010 ⚠️ *see below* | 1.304 ± 0.042 | **0.772** |

- **Conditioning width matches task width.** Narrow steers its axis harder (11.2× pooled σ,
  p = 0.0040); broad is required to express a multi-property request at all (7.6× pooled σ on top-50).
- **Training on good data raises the floor and buys no control.** Stage 4 has the best unconditional
  QED of any arm and is ~10× worse on the joint target.
- **RL did not add control beyond conditioning.** Stage 3 vs Stage 2 separates on neither metric
  (1.36× and 0.55× pooled σ, ranges overlap on both). A genuine null.

---

## ⚠️ Two numbers that mislead if quoted alone

**1. Stage 4's steering range (0.577) is not steering.** It is the spread of a *non-monotonic* response:

| requested QED | 0.3 | 0.4 | 0.5 | 0.6 | 0.7 | 0.8 | 0.9 |
|---|---|---|---|---|---|---|---|
| Stage 4 achieved | 0.198 | 0.307 | 0.423 | **0.769** | **0.774** | **0.465** | **0.430** |

Stages 1–3 rise monotonically across the same sweep. Stage 4 was trained always-null, so the harness
feeds it out-of-distribution conditioning and its response is arbitrary. **The non-response is the
measurement.** Quote the curve, or quote the range with this attached — never the range alone.

**2. Stage 3's null is bounded.** Supported: *at `lr=1e-5`, 1000 steps, with a KL anchor, RL did not
beat conditioning here.* Not supported: *RL cannot help.*

## Which folder to use

| package | status |
|---|---|
| **`paper/`** | ✅ **AUTHORITATIVE** — the four-arm comparative package |
| `archive/results/{stage1_ablation,phase2_results,steering_investigation}` | ⛔ **superseded** — earlier training and evaluation configurations, moved out of this folder to `archive/`. Retained for provenance. **Do not cite.** |

Superseded packages (now under `archive/results/`) carry no warning inside their individual CSVs and figures. **Do not lift a number
out of one without checking here first.** They are kept only so earlier runs remain reconstructable.

Generated by `notebooks/generate_results.py` (notebook CELL 30). Register a new arm by adding one line
to its `ARMS` list; every table, figure and statistic picks it up automatically.

### Layout inside `paper/`

```
paper/
  comparison/        csv · figures · tables      <- all arms together
  stage1_qedonly/    csv · figures · tables · molecules
  stage2_multiprop/ · stage3_rl/ · stage4_filtered/
  config/ · manifest.json
```

**One measurement pass, two views.** Per-stage outputs are slices of the same generated molecules that
produce the comparison tables, so a per-stage number cannot disagree with the comparison — and one
cannot be regenerated without the other. Use **`comparison/`** for anything contrasting arms; use a
stage folder for that arm on its own. Each stage's `molecules/` holds generated SMILES: per QED target,
an unconditional sample, and the top-50 joint-target candidates.

⚠️ Adding an arm means a **full re-run** — every arm is re-measured in the same pass. Existing arms'
numbers shift within seed noise; that is expected, and the comparison table is what is authoritative.

📌 `image.png` at the package root is a manually saved figure, not generator output.

📌 **Stage 3's β frontier lives on Drive, not here** — `stage3_rl/beta_frontier.csv`,
`beta_frontier.png` and `promoted.json` sit beside the checkpoints under
`MyDrive/Models/D3PM_Ultimate/`. The frontier is a reportable result; if it is cited, copy those three
files into the repo first.

## What is measured

| section | question |
|---|---|
| 1. QED targeting | can the arm hit a requested QED? reported per target, and as **steering range** (max − min achieved) |
| 2. MW targeting | can it hit a requested molecular weight? *(arms that can express it — Stages 2 and 3)* |
| 3. Joint target | `{qed 0.8, mw 350, sa_score 2.5}` — multi-objective control |
| 4. QC | validity, uniqueness, novelty, SA, mean MW/HA, internal diversity |
| 5. Sampler characterisation | temperature × noise frontier, padding-penalty sweep *(reference arm, single seed — it characterises the sampler, not an arm)* |

Distribution match against the training set is covered by QC's `meanMW` / `meanHA` / `meanQED` read
against the dataset moments in `config/norm_stats.json`, rather than as a separate section.

---

## Rules for using these numbers

1. **Everything comparative is measured over 5 seeds and reported as mean ± s.d.**
   A single-draw arm cannot be compared against a replicated one. Any new arm goes through the same
   harness — no exceptions, or the comparison is void.

2. **Report top-50 on the joint target, never top-1.** The best single candidate of 512 has a
   seed-to-seed CV near 90% and does not separate arms. Top-50 is the stable discriminator.

3. **Operating point:** `cfg=1.0, temp=0.4, noise=0.5, pad_penalty=1.0, steps=50, min_len=12`,
   identical for every arm. Note `cfg=1.0` means classifier-free guidance amplification is **off** —
   all reported control comes from the raw conditional, which is a deliberately conservative setting.

4. **Arms receive only the properties they can express.** Stages 1 and 4 have no input slot for MW or
   SA, so on the joint target they receive the QED component alone. That asymmetry *is* the comparison
   — it is why conditioning width is a design decision — not a confound to correct for.

5. **`hERG` and `pchembl_mean` are trained into Stages 2 and 3 but cannot be evaluated.** The ADMETlab
   values exist only for training molecules and there is no live predictor for novel structures. Every
   evaluation here uses RDKit-computable properties (`qed`, `mw`, `sa_score`). No claim about those two
   axes is supported until a surrogate scorer exists.

6. **`stage2_norm_stats.json` is canonical.** All arms are z-scored against these moments — including
   Stage 4, which loads them rather than recomputing on its filtered subset. Never regenerate it.
